# 论文速读：LegalAgentBench: Evaluating LLM Agents in Legal Domain

## 一句话总结
本文提出了 LegalAgentBench，首个专为评估中文法律领域 LLM 智能体能力设计的综合基准。该基准包含 17 个真实法律语料库、37 个专业工具及 300 个标注任务，并通过引入过程级关键词（key_middle）计算进度率，实现对智能体中间推理步骤的细粒度评估。

## 研究问题与动机
1. **现有通用基准缺乏法律专业性**：AgentBench、ToolBench 等通用领域基准无法充分捕捉法律场景中司法认知与决策的复杂性和微妙细节，其评估结果对法律等专业领域的参考价值有限。
2. **现有法律数据集任务过于基础**：当前法律领域数据集（如 LexEval、LegalBench）主要聚焦于案例检索、判决预测等单一基础任务，难以评估多步推理、复杂论证和法律写作等进阶能力。
3. **缺乏智能体交互范式评测**：现有基准多为静态问答形式，未考虑 LLM-as-Agent 在实际法律场景中通过工具调用、逐步推理解决问题的交互能力。
4. **评估粒度不足**：传统成功/失败二元评估无法区分"接近完成"与"完全未完成"的任务，难以揭示智能体的真实能力层次。

## 核心贡献（创新点）
1. **首个法律领域 LLM 智能体专用基准**：构建了涵盖 17 个真实法律语料库和 37 个专业工具的完整评测环境，填补了法律垂直领域智能体评测的空白。
2. **可扩展的任务自动构建框架**：提出基于规划树的六步任务构建流程（规划树构建→路径选择→实体选择→问题重写→答案生成→人工验证），可生成 1-5 跳多步推理任务及写作任务，支持新知识库的动态扩展。
3. **过程级细粒度评估指标**：在最终答案关键词（key_answer）基础上引入中间步骤关键词（key_middle），提出成功率与进度率双指标，实现对智能体推理过程的量化分析。
4. **全面的模型能力剖析**：对 8 个主流 LLM 在三种推理范式（Plan-and-Solve、Plan-and-Execute、ReAct）下进行评估，揭示了各模型在法律场景下的优势、局限及改进方向。

## 方法详解
**环境设计**：
- **语料库**：17 个真实法律数据源，包含 14 个表格数据库（上市公司信息、法院信息、案件信息等）和 3 个文档集合（法律知识、法律条文、指导案例）。
- **工具集**：37 个专业化工具，分为四类：
  - 文本检索器（3个）：基于 Embedding-3 的法律知识/条文/案例检索
  - 数学工具（5个）：加减乘除、排序、最值计算
  - 数据库工具（28个）：针对各表格库的结构化查询，支持 Column 参数控制返回字段
  - 系统工具（1个）：Finish，用于汇总输出最终答案

**任务定义与交互范式**：
在时间步 t，智能体执行动作 $a_t$，接收观测 $o_t$，更新状态 $s_t$：
- 状态更新：$s_{t+1} = u(s_t, a_t, o_t)$
- 动作决策：$a_t = \pi(s_t, o_1, o_2, ..., o_{t-1})$
- 反馈函数：$o_t = f(a_t)$，有效动作返回结果，否则返回错误信息
- 最大迭代上限 T=10，超限或主动 Finish 时终止

**任务构建框架**：
1. **规划树构建**：以未知实体为根节点，工具调用关系为分支，形成多层解决方案路径
2. **路径选择**：分层采样 1-5 跳串行路径，并引入并行工具调用（如写作任务中同时查询原被告信息及法律依据）
3. **实体选择**：迭代验证实体可执行性，确保工具调用不返回空结果
4. **问题重写**：使用 GPT-4 将机械的多跳问题改写为贴近真实法律咨询自然表述
5. **答案生成**：基于已知工具链程序化提取正确答案
6. **人工验证**：法律专家逐一审核问题、路径、答案的准确性与合规性

**评估指标**：
- **成功率**：$s_i = |\mathcal{M}_i| / |\mathcal{K}_i|$，其中 $\mathcal{M}_i$ 为模型输出中出现的关键词集合，$\mathcal{K}_i = key\_answer$
- **进度率**：$\mathcal{K}_i = key\_answer \cup key\_middle$，纳入中间步骤关键词，提供更细粒度评估
- **BERTScore**：衡量生成文本与参考答案的语义相似度

## 实验与结果
**实验设置**：
- **基线模型**：GLM-4、GLM-4-Plus、LLaMA3.1-8B-Instruct、Qwen-max、Claude-Sonnet、GPT-3.5、GPT-4o-mini、GPT-4o
- **推理方法**：Plan-and-Solve (P-S)、Plan-and-Execute (P-E)、ReAct
- **全部 temperature=0**，3-shot 示例引导

**主要结果（成功率）**：

| 模型 | 最佳方法 | ALL 成功率 | 1-hop | 5-hop | Writing |
|------|----------|------------|-------|-------|---------|
| **GPT-4o** | ReAct | **79.08%** | 92.62% | 61.17% | 65.41% |
| GLM-4-Plus | ReAct | 74.99% | 91.31% | 43.00% | 76.59% |
| Qwen-max | ReAct | 74.22% | 90.62% | 60.83% | 66.62% |
| Claude-Sonnet | P-E | 67.03% | 87.00% | 47.17% | 86.10% |
| GPT-3.5 | ReAct | 29.86% | 64.21% | 13.33% | 8.52% |
| LLaMA3.1-8B | ReAct | 23.59% | 60.19% | 6.00% | 8.72% |

**关键发现**：
- GPT-4o 在 ReAct 下综合表现最佳（79.08%），且 Token 消耗相对较低（11.2M）
- GLM-4-Plus 在进度率上全面超越 GPT-4o，表明其中间推理过程更完整
- 多跳推理随 hop 数增加性能显著下降（1-hop 最高 93%→5-hop 约 61%）
- **写作任务中 ReAct 表现反而落后**：因逐步更新机制在遇到错误时重复尝试单步，错过并行处理机会
- 相同模型不同推理方法性能差距可达 65%，凸显推理策略对法律任务的重要性
- 小模型（GPT-3.5、LLaMA3.1-8B）工具调用能力严重不足，成功率低于 30%

## 相关工作脉络
1. **AgentBench (Liu et al., 2023b)**：通用领域多维智能体评测基准，覆盖 OS、数据库、知识图谱等 8 种环境；与本文定位差异在于缺乏法律垂直领域的专业工具和任务设计。
2. **ToolBench (Qin et al., 2023) / ToolQA (Zhuang et al., 2023)**：聚焦工具调用能力的通用基准；前者覆盖 16000+ API，后者设计需外部工具辅助的问题；本文差异在于工具均为法律领域专用，任务设计融入真实法律场景。
3. **T-Eval (Chen et al., 2024)**：从规划、推理、检索等 6 个维度分解工具使用能力；本文与之互补，T-Eval 侧重能力分解，本文侧重完整法律任务流程的端到端评估。
4. **LegalBench (Guha et al., 2024)**：英文法律推理评测基准；本文是其中文版本且首次引入智能体交互范式，支持多步工具调用。
5. **LexEval (Li et al., 2024d)**：中文法律 LLM 评测基准；以静态问答为主，本文扩展至智能体交互式多步推理。
6. **AgentBoard (Ma et al., 2024)**：引入进度率指标的评估框架；本文借鉴并扩展该思路，结合法律领域特点设计 key_middle 机制。

## 局限性与未来方向
1. **语言与法系局限**：当前基准仅支持中文和大陆法系，未来需扩展至英文及其他法系（如判例法），以增强普适性。
2. **语料规模与动态性**：17 个语料库虽覆盖典型法律场景，但数据量相对有限，且法律条文和案例持续更新，需建立动态维护机制。
3. **写作任务评估不足**：写作任务依赖关键词匹配，难以全面评估法律文书的逻辑性、规范性与论证质量，需探索更专业的评估方法。
4. **智能体架构探索有限**：本文仅评估三种基础推理范式，未深入探索记忆机制、反思机制、多智能体协作等高级智能体设计对法律任务的影响。
5. **人机协作边界未明**：未系统研究何种任务适合完全自动化、何种需要人工介入，未来需结合法律从业者反馈优化智能体部署策略。

## 研究启发与可借鉴点
1. **可扩展任务构建框架可迁移**：基于规划树的六步构建流程（路径枚举→路径选择→实体验证→问题重写→自动答案生成→人工审核）具有高度通用性，可直接迁移至医疗、金融、教育等其他垂直领域。
2. **过程级细粒度评估指标设计精巧**：key_middle 机制通过提取工具调用结果的关键词作为中间评估目标，为多步推理任务的评估提供了可操作方案，可应用于代码生成、数学推理等需多步求解的场景。
3. **并行工具调用范式值得借鉴**：写作任务中引入并行工具调用（同时查询多方信息并综合法律依据）反映了真实法律工作的复杂性，可在复杂报告生成、多文档摘要等任务中复用此设计。
4. **真实语料库的动态更新策略**：采用公开法律数据源（公司登记信息、法院数据、裁判文书等）而非静态训练集，降低了数据污染风险，这一思路可推广至任何需要防过拟合的评测场景。
5. **推理方法与任务类型的交互效应分析**：ReAct 在多跳推理上优于规划方法，但在写作任务上反被 P-E 超越的发现，揭示了任务类型对推理方法选择的关键影响，提示后续研究应针对任务特征定制推理策略。

## 关键术语表
**LegalAgentBench**：面向中文法律领域的 LLM 智能体评测基准，包含 17 个语料库、37 个工具和 300 个标注任务。

**ReAct**：Reasoning and Acting 的缩写，一种交替进行推理（Thought）和行动（Action）的智能体交互范式。

**Plan-and-Solve (P-S)**：先完整规划所有步骤再逐步执行的智能体推理方法。

**Plan-and-Execute (P-E)**：在执行过程中可根据中间结果动态调整计划的智能体推理方法。

**key_answer**：最终答案中需要命中验证的关键词集合，用于计算成功率。

**key_middle**：中间推理步骤中需要命中的关键词集合，用于计算进度率，实现细粒度评估。

**规划树（Planning Tree）**：以未知实体为根节点、工具调用关系为分支的树状结构，用于系统化构建多跳任务。

**进程率（Process Rate）**：基于 key_middle 和 key_answer 综合计算的细粒度评估指标，反映智能体中间步骤的完成情况。
