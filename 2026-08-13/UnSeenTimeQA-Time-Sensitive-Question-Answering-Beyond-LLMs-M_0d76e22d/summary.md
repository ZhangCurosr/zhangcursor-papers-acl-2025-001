# 论文速读：UnSeenTimeQA-Time-Sensitive-Question-Answering-Beyond-LLMs-M

## 一句话总结
本文提出了 UnSeenTimeQA，一个基于合成事实的数据污染零泄漏的时间敏感问答（TSQA）基准测试。该基准通过物流规划场景自动生成题目，强制大语言模型在切断预训练知识依赖的前提下进行严格的时序推理，并首次将并行事件执行纳入评估体系。

## 研究问题与动机
- **现有 TSQA 基准存在严重数据污染**：TimeQA、TempReason、MenatQA 等基于维基百科等现实世界事实构建，题目在 LLM 预训练阶段已广泛存在于互联网，模型高分主要源于参数记忆而非真正的时序推理。
- **后截止期基准难以持续维护**：RealTimeQA、FreshQA、TAQA 等试图通过延后发布时间规避污染，但依赖人工持续更新；一旦更新停止，新发布的 LLM 会迅速将公开数据纳入预训练语料，污染风险再次出现。
- **现有基准缺乏并行事件推理场景**：既有工作主要关注事件的串行顺序关系，忽略了多事件并发执行（如同时装载多个包裹、资源竞争）对复杂时序推理的要求，评估维度存在结构性缺失。
- **缺乏可控且可无限扩展的评测工具**：现有基准数据规模固定、更新成本高，无法应对 LLM 快速迭代带来的评测失效问题，亟需一种按需生成、逻辑自洽的合成数据框架。

## 核心贡献（创新点）
- **实证揭示了现有 TSQA 基准的“记忆幻觉”问题**：通过上下文与实体篡改对照实验，证明 GPT-4 在现实基准上的表现高度依赖预训练记忆，一旦引入冲突事实即急剧下降。
- **提出首个完全去污染的时间敏感问答基准 UnSeenTimeQA**：采用合成物流场景事实替代真实世界知识，从根源上切断预训练数据泄漏路径，实现真正意义上的零数据污染评测。
- **首次将并行事件执行纳入 TSQA 评估体系**：突破以往仅关注串行事件序列的局限，设计 Hard (Parallel) 难度级别，考察模型对并发事件时间重叠与状态共享的推理能力。
- **提供开源的按需数据生成框架**：基于 ActionReasoning-Bench 的规划求解流水线，支持随时生成任意数量、不同深度与难度的新样本，彻底解决基准老化与人工更新成本高的问题。
- **系统性评测与细粒度误差归因**：在五个主流 LLM 上完成 Zero-shot/Few-shot 评估，定位了模型在长程依赖跟踪与并行事件处理上的核心失败模式。

## 方法详解
- **领域与场景设计**：受国际规划竞赛（IPC）物流问题启发，构建包含城市、位置、卡车、飞机、包裹的封闭环境。事件类型限定为 load/unload truck/plane 与 drive/fly，所有题目答案均可通过内部状态转移逻辑推导，无需调用外部常识。
- **时间信息分层（难度控制）**：
  - **Easy**：提供每个事件的精确开始与结束时间戳，模型可直接提取顺序。
  - **Medium**：提供开始时间与持续时间（Duration），需模型自行推算结束时间。
  - **Hard**：仅提供持续时间，不给出绝对时间指示，需通过事件依赖关系累加推导时间线。Hard 进一步划分为 Serial（串行）与 Parallel（并行）两类。
- **问题类型设计**：
  - **Static-Time**：询问特定绝对时间点某包裹的位置。
  - **Relative-Time**：询问相对于某一时间的偏移量（如“X小时后”）的位置。
  - **Hypothetical-Time**：假设某一事件被延迟或加速，询问在变化后的反事实时间线中某时刻的状态，强制模型进行轨迹重推演。
- **数据生成与质量控制**：利用规划求解器生成合法事件序列，添加随机持续时间后通过多模板自然语言化表达以保证语言多样性。引入深度（Depth）指标（目标事件与起始事件在序列中的绝对位置差，范围 6-20）进行分层采样，确保复杂度均衡。总样本量 10,800（4难度×3题型×3次采样×300题）。
- **Prompt 结构**：严格包含 `[Domain Description]` + `[Object Description]` + `[Initial States]` + `[Event Sequence]` + `[Question]`，末尾附加 CoT 指令 `Let's think step-by-step...` 引导分步推理。
